## أ) Render Free — 3 دقايق، بلا كارت

`render-free.yaml` في جذر المستودع مضبوط على الخطة المجانية ومعه تعطيل النشر التلقائي.

1. [dashboard.render.com](https://dashboard.render.com) → **Sign in with GitHub**.
2. **New** → **Blueprint** → اختر مستودع `JasonWade45/ACQ-GreenseedTX`.
3. في خانة **Blueprint file path** اكتب: `render-free.yaml`
   (وليس `render.yaml` — ذاك يحتاج خطة مدفوعة وقرصًا دائمًا).
4. عند الطلب اكتب `APP_ACCESS_PASSWORD` (12 حرفًا على الأقل).
5. **Apply**، وانتظر 3–5 دقايق، ثم افتح الرابط:
   `https://acq-assistant-xxxx.onrender.com`

### حدوده الحقيقية

- **لا قرص دائم:** قاعدة SQLite تُمحى مع كل deploy وكل إعادة تشغيل. النشر التلقائي معطَّل
  في الملف حتى لا يمسحها `git push` من غير قصد.
- **ينام بعد ~15 دقيقة خمول:** أول زيارة بعد النوم تاخذ 30–60 ثانية. هذا سلوك الخطة لا عطل.
- **½ جيجا ذاكرة:** كافية لهذا النظام، لكن الاستيراد الكبير سيكون أبطأ من سيرفر حقيقي.

### كيف تحمي عملك على خطة مجانية

النظام يصدّر كل العملاء إلى CSV: من الواجهة زر **Export**، أو مباشرة:

```bash
curl -H "Authorization: Bearer <TOKEN>" https://<الرابط>/api/leads/export -o seller-leads.csv
```

صدّر قبل أن تترك الجلسة، وأعد الاستيراد من **Import Center** في الجلسة التالية.

## ب) Oracle Cloud Always Free — لينكس مجاني للأبد وبيانات دائمة

هذه هي الطريقة الوحيدة للحصول على **سيرفر لينكس حقيقي مجانًا بلا نهاية**، وهو نفس مسار
النشر في `docs/DEPLOY_SERVER_AR.md` بلا أي تغيير.

1. أنشئ حسابًا على [cloud.oracle.com](https://cloud.oracle.com) واختر **Always Free**.
   يُطلب كارت للتحقق فقط، والموارد المجانية لا تُخصم.
2. أنشئ VM: **Ampere A1** (حتى 4 أنوية/24 جيجا) أو **VM.Standard.E2.1.Micro**، بصورة
   **Ubuntu 24.04**. أضف مفتاح SSH واحفظه.
3. في **Security List** الخاص بالشبكة أضف قاعدة Ingress للـ TCP على المنفذ `8000`
   (و`80`/`443` إن كان لديك نطاق).
4. اتصل بالسيرفر ثم شغّل التثبيت:

```bash
ssh ubuntu@IP-السيرفر
```

```bash
curl -fsSL https://raw.githubusercontent.com/JasonWade45/ACQ-GreenseedTX/main/deploy/install.sh -o /tmp/acq.sh
sudo bash /tmp/acq.sh --domain IP-السيرفر --no-https
```

> `install.sh` يتحقّق من صيغة النطاق، لذا بلا نطاق استخدم الأمر اليدوي في
> `docs/DEPLOY_SERVER_AR.md` (المسار ج) واضبط `APP_HOST=0.0.0.0` و`APP_ACCESS_PASSWORD`
> في `deploy/.env`، ثم `docker compose up -d --build`.

5. افتح `http://IP-السيرفر:8000` — ستظهر شاشة الدخول لأن `APP_ACCESS_PASSWORD` مضبوطة.

### تنبيه أمني لهذا المسار

بلا نطاق لا يوجد HTTPS، وكلمة المرور تُرسل عبر اتصال غير مشفّر. لذلك:

- استخدمه من شبكة تثق بها، أو
- أضف نطاقًا مجانيًا (مثل `duckdns.org`) ومرّر `--domain` للـCaddy ليعمل HTTPS تلقائيًا،
  أو
- افتح المنفذ عبر `ssh -L 8000:127.0.0.1:8000 ubuntu@IP` من جهازك فقط.

## ما لا يستحق التجربة

| المنصة | لماذا لا |
|---|---|
| **Vercel** | نظام بقرص للقراءة فقط + نسخ متوازية ⇒ كل نسخة قاعدة منفصلة وكل كتابة تفشل. |
| **Netlify / GitHub Pages** | استاتيك فقط، لا Python ولا SQLite. |
| **Fly.io / Railway** | لم يبقَ فيهما استحقاق مجاني فعّال؛ يُطلب رصيد مدفوع. |
| **Hugging Face Spaces** | مجاني، لكن التخزين مؤقت ما لم تُدفع مساحة دائمة. |
| **Cloudflare Tunnel من جهازك** | مجاني ويعمل، لكنه **نشر على ويندوز/جهازك** — مرفوض صراحة. |

## الخلاصة

- **عرض وتجربة اليوم:** المسار (أ) — ريندر مجاني، 3 دقايق.
- **عمل حقيقي ببلاش:** المسار (ب) — أوراكل Always Free، بيانات دائمة، بلا فاتورة.

**لم يُتحقَّق منه في هذه البيئة:** إنشاء الخدمة على Render، والتسجيل في Oracle، وتنفيذ
`docker compose` على سيرفر حقيقي. التحقق الممكن هنا هو صحة ملفات الإعداد ومنطق
التثبيت وكلمة المرور والاستيراد والتصدير — وقد نُفِّذت فعليًا.
