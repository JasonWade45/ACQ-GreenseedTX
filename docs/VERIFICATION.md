## Maintenance and archive checks

The current 1.2 maintenance smoke ran the actual CLI in a space-containing path: migrate → explicit fictional sync → online backup → refused backup overwrite → refused unconfirmed restore → restore → alter only the disposable target → restore with recovery copy. Every source-table value matched after restoration. The recovery copy retained the previous target-only marker. A GitHub-schema restore was refused, source/backup hashes stayed unchanged and integrity/FKs passed.

`scripts/package_release.py` packages allowlisted public source/tests/docs/fictional fixtures and `frontend/dist`. It excludes DB/WAL/snapshots, private environment/password files, dependencies/caches/logs and downloaded raw documentation JS. It embeds a per-file SHA-256 manifest and produces a ZIP checksum.

`scripts/test_release.py` verifies every manifest entry and archive exclusion, extracts into a **path containing spaces**, then runs the extracted app's actual lifespan/TestClient using this interpreter's installed dependencies. It checks a fresh zero-seller DB/head/tables/integrity/FKs, compiled SPA/assets and client-side routes, authenticated API, disabled/unconfigured providers, per-request consent and local Host/rebinding refusal. This is a real extracted Linux boot, **not native Windows helper execution or a clean offline Python dependency install**.
